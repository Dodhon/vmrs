## 1. An Introduction to VMRS<sup>™</sup>
#### What is VMRS?
Since 1970, the purpose of VMRS has been to provide a vital communication link between maintenance personnel, computers, and management. It establishes a "universal" language for fleets, original equipment manufacturers' (OEMs), industry suppliers, computers, and those people whose responsibility it is to specify, purchase, operate, and maintain equipment.
Developed by and for equipment users under the auspices of American Trucking Associations, VMRS provides the discipline necessary for different industry segments to communicate with each other. VMRS is the shorthand of maintenance reporting, eliminating the need for extensive written communications with all the inherent problems of miscommunication normally associated with the written word.
To meet the ever-changing needs of the equipment industry, the Technology & Maintenance Council (TMC) of American Trucking Associations serves as the official custodian of VMRS. TMC provides OEMs, manufacturers, part suppliers, and equipment users with updated codes on an "as needed" basis reflective of current equipment design and the informational needs of the VMRS user.
VMRS<sup>™</sup> Version 2.0 is the latest version of the VMRS coding convention, established more than 45 years ago. Since its inception, VMRS has a undergone a significant evolution. Based on user requests, TMC has:
Expanded Code Key 31 to accommodate an ever-increasing interest in the unique reporting needs of the "off-highway" or "stationary equipment" market. As a result, TMC has made full use of the expanded three-digit code so that these equipment types are addressed. For example, System Code (X6X) has been created to accommodate "equipment dependent attachments." The introduction of this system allows users to track the expense associated with major attachments (those that warrant their own asset number) that are only operational when attached to a "host" piece of equipment (i.e. a truck mounted snow blower, or perhaps a plow).
- Increased the total number of codes in Code Key 33, "Component Codes" to more than 34,000.
- Added Code Key 23, which covers tire position codes; Code Key 24, covering maintenance status codes; Code Key 83, which covers claim response reason, and Code Key 84, which covers claim response status.
- Expanded to Code Key 15, "Work Accomplished" and Code Key 18, "Technician Failure Code" to satisfy customer demands.
- Expanded Code Key 34, which is used to identify more than 11,000 manufacturers, suppliers, and brands.
- Expanded Code Keys 1, 2, 10 and 48, which describe equipment vocations, categories and body types. These codes now accommodate many industries beyond trucking, such as transit, off-highway and construction industries.
- Instituted a Certified VMRS Specialist program to recognize proficiency in VMRS nomenclature, structure, and usage.
- Diversified the VMRS<sup>™</sup> licensing offerings to encourage consistent and appropriate industry use of VMRS.
- Developed customized VMRS training options for in-person and virtual learning.
- Applied VMRS to industry benchmarking programs, such as the TMC/FleetNetAmerica Vertical Roadside Breakdown Benchmarking Program.
#### A Structured Coding System
VMRS is a structured coding system, providing the discipline necessary to operate in today's computer-based information age or — where desired — as a completely manual system. Simple in concept, VMRS can be used at any level, from total operating systems down to the individual part level. The level of coding used is entirely up to the user. One can select the level of reporting detail at any time without the need to redesign the coding structure or implement costly new programs. No matter which level the user selects, the data collected can be compared directly to data collected by others at the same or higher VMRS coding level.
The coding structure encompasses most equipment found within today's transportation activities including trucks, tractors, trailers, forklifts, shop equipment, off-road vehicles, utility vehicles, etc.
#### **Recognized Internationally**
Today, equipment users worldwide use VMRS to capture and report their equipment maintenance activities. Equipment manufacturers and maintenance software suppliers use VMRS coding for parts, thus providing additional impetus for fleets to adopt this universal coding scheme.
A complete service industry has grown up around VMRS, with a number of firms offering VMRS computerized reporting systems and/ or services to fleets. This manual will help your software provider utilize VMRS to your mutual benefit.
#### **15 Distinct Advantages to VMRS**
There are 15 distinct advantages to using VMRS:
- 1. VMRS is Easy to Use—VMRS was designed for use at the shop level. Accurate and easily understood reporting by the mechanic is essential if any information system is to succeed. At the higher level, management must understand what the mechanic has accomplished. VMRS meets both criteria.
- 2. VMRS is Cost Effective—TMC has undertaken the initial cost normally associated with developing such a system. The practicality of the system has been proven, in that VMRS has been in continuous use since 1970. TMC keeps the system dynamic, thus eliminating the need for individual users to continually research and update their systems.
- 3. Follows Accepted Accounting Practices—The VMRS code structure al-
lows the user to comply with the needs of most recognized accounting disciplines. VMRS provides the flexibility to properly massage data to meet both immediate and long-term needs.
#### 4. VMRS Enables Sound Budgeting—
VMRS provides a sound basis for budget preparation and forecasting based on fleet mix, projected utilization, and historic performance. Requests for additional mechanics, increased parts inventory, special equipment, or expanded facilities can readily be supported by data captured using VMRS. VMRS is invaluable in determining how many pieces of equipment are required to support a given workload. The same data can be used to determine the mechanic/parts mix required to support various equipment mixes and utilization criteria.
5. VMRS Helps Control Costs—VMRS provides detailed records of the maintenance activity comprising both equipment and facilities. It identifies where monies were spent, at which point in the life of a piece of equipment repairs were performed, and details the expenses incurred in the supporting activity. Distribution between parts and labor is an inherent part of the VMRS reporting structure, thus allowing analysis of what occurred and when. This is important in determining the cause-and-effect relationship of maintenance.
#### 6. VMRS Improves Facility
Management—VMRS provides the ideal basis for establishing a facility management program. The coding structure provides the basis for complete labor and material distribution, direct and indirect, thus allowing management the opportunity to analyze in detail each cost segment. With this information, management can take whatever action is deemed appropriate to correct those situations which appear out of line. This information provides the necessary input for most purchasing decisions.
7. VMRS Tracks Labor Distribution—VMRS provides complete labor distribution cover-
ing both direct and indirect labor.
- VMRS Helps Control Parts Inventory
–VMRS was developed, and is used within the industry, as the basis of many successful parts inventory control systems. Some fleets have developed their own systems using VMRS, while others utilize off-the-shelf programs designed and built around the VMRS coding structure. VMRS provides complete details as to parts use, thus identifying which part should be inventoried and which should be procured on an "as needed" basis. For those states having an Inventory Tax, VMRS provides documented back-up.
- 9. VMRS Supports Warranty Claims—The VMRS coding structure incorporates the capability to record and isolate those costs normally associated with warranty. Being a universal language, accepted and endorsed by equipment manufacturers and industry suppliers, VMRS provides the ideal audit trail for instituting and supporting warranty claims. New Code Keys have been developed exclusively for warranty, such as Code Key 81 Type of Claim, Code Key 83 Response Reason Code and Code Key 84 Claim Response Status Code.
- 10. VMRS Improves Preventive
Maintenance Programs—VMRS provides the ideal basis for determining the effectiveness of the PM program. Are PMs being performed too often or not often enough? Should PM intervals or their scopes be modified based on specific failures reported through maintenance reporting? What staffing is required to perform PMs? VMRS provides the answers.
#### 11. VMRS Helps Benchmark
**Equipment and Labor Productivity**—The standards provide data necessary for measuring labor productivity. The relationship between direct and indirect labor can be evaluated and changes implemented as needed. Parts/labor ratios can be established that provide the lowest overall maintenance costs. VMRS provides the basis for establishing the economic break-
point between parts replacement and parts repair. Equipment utilization, an important ingredient in transportation, is impacted by maintenance. VMRS provides the means for recording downtime and identifying the specific reason for excessive delays.
#### 12. VMRS Helps Benchmark
**Component Performance**—VMRS provides the data for measuring performance and reliability of specific components and/or parts. A determination can be made of first failure (normally attributed to the equipment manufacturer) and subsequent failure (normally attributed to maintenance).
#### 13. VMRS Assists in Equipment
**Replacement Decisions**—VMRS can substantiate requests for new or replacement equipment based on current rather than historic information. Maintenance support requirements can be determined for each class of equipment being operated. This allows management to quickly determine whether it is more economical to replace or repair and what support is required in the way of labor and material for any combination of new and/or used equipment.
- **14. VMRS Satisfies Reporting Requirements**—VMRS allows fleets to fulfill the ever-changing reporting requirements dictated by government agencies.
- **15. VMRS-Compatible Software is Widely Available**—Many software suppliers currently offer complete turnkey VMRSbased maintenance programs. Many of these can provide custom-made reports to suit the specific needs of the user. Software is also available from a number of sources allowing in-house processing of VMRS.

## Requirements for Using VMRS<sup>™</sup>
#### What Are the Basic Requirements for Implementing VMRS?
All external reporting and data interchange must adhere to VMRS coding conventions as defined herein or further described in this VMRS™ Implementation Handbook.
Internal reporting may use other techniques; however, all external interchange of information must be converted to VMRS using direct correlations. No assumptions, prorations, or averages can be used in any conversions.
Full implementation of VMRS<sup>TM</sup> uses nine key VMRS components. Unless each of the nine items listed below can be checked "yes," the user is not implementing VMRS<sup>™</sup> correctly and will be unable to obtain credible or meaningful direct comparisons from any VMRS data base or other VMRS participant.
#### YES Does the System Do the Following?
- Use the VMRS Equipment Master Record.
- Identify Equipment Vocation — Code Key 1.
- Segregate costs by Reason for Repair— Code Key 14
- Identify work accomplished using VMRS Coding—Code Key 15
- At minimum, identify systems via the three-digit VMRS System Code —Code Key 31
- For more detail, identify assemblies via the three-digit VMRS Assembly Code—Code Key 32
- For even more detail, identify individual parts via the three-digit VMRS Component Code—Code Key 33.
- Identify part/equipment manufacturers, suppliers or brands universally using Code Key 34.
- Have the capability to record VMRS Technician Failure Codes—Code Key 18.
Let's now look at each of these nine VMRS components to see how VMRS works.
#### The Equipment Master Record
What is a piece of equipment? It is not just a year, make, and model, but rather a unique series of components assembled to perform a specific task. Under VMRS, each of these components can be followed and monitored on an independent basis or as a total piece of equipment. The sum of the costs of maintaining the components represents total equipment maintenance cost.
VMRS uses a Equipment Master Record (similar to a birth certificate) to record many of the items appearing on the manufacturer's line set tickets. The Equipment Master Record Form allows for consolidation of data from all manufacturers into a uniform format.

To this end, TMC has expanded these codes to meet additional equipment user needs. Using Code Key 1, for example, allows linehaul costs to be identified and separated from pickup and delivery and/or other equipment assignments.
Code Key 1 identifies the primary activity or vocation to which a unit has been assigned— "what the equipment does." #### Reason for Repair Codes: Code Key 14
Identifying what caused a piece of equipment to come in for repair is essential to proper equipment management. VMRS provides for the segregation of this activity in one of the three following areas:
Maintenance—This represents all monies spent on equipment to keep it operational, and could be used to affect management's decision to purchase that piece of equipment again. Monies spent in this category directly influence the replacement decision.
- 2. **Management Decision**—This category identifies and isolates all monies spent which are neither the equipment's nor manufacturer's fault and over which management has direct control. An example would be the cost of adding new logos onto a piece of equipment.
- Outside Influence—Those items, over which neither the manufacturer nor the user have direct control, are classified in this category.

#### Assembly Level Codes: Code Key 32
Through the use of assembly level codes, VMRS provides additional capability to further define Code Key 31's System Codes. The first classification below the system level is referred to as
the assembly. At this level, all major groupings within each system are broken out and reported through the use of a three digit code. These, when used with their system prefix, identify the specific assembly within a piece of equipment. For example, front brakes and drums can be identified by a combination of the System and Assembly Code 013-001. A complete listing of Code Key 32 appears elsewhere in this *Handbook*.
#### Component Level Codes: Code Key 33
In order to provide a common generic term for each part within a piece of equipment, the system and assembly codes are further subdivided to the component level. This is accomplished through the use of an additional three digit part identifier code. These codes should not be confused with the manufacturers' or suppliers' unique identification (part) numbers, but rather should be considered universal identifiers or generic terms for the part. For example, a front brake lining can be identified by the following combination of System/Assembly/Component codes—013-001-015. A complete listing of Code Key 33 appears elsewhere in this *Handbook*.
#### Manufacturer/Supplier/Brand Identification: Code Key 34
In order not to disturb either the manufacturers' or suppliers' unique numbering system, VMRS uses its own generic means of identifying manufacturers/suppliers or their brands. The identifier is a five-character alpha code, assigned by TMC.
It used as a prefix to the manufacturers' and/or suppliers' unique number. It is not the intent of VMRS to supplant the manufacturers'/suppliers' unique part numbering systems, but rather to supplement them.
When a Code Key 34 manufacturer's (or brand) code and part number are used in conjunction with the VMRS System/Assembly/Component level codes (Code Key 33), precise identification of a specific part is possible on a universal basis. This commonality of identification on a consistent basis is a prerequisite to developing an industry database for analysis of maintenance information or for mutually exchanging information on a meaningful basis. A complete listing of Code Key 34 appears elsewhere in this *Handbook*.

## 3. How to Implement VMRS<sup>™</sup>
This section provides guidelines for implementing VMRS<sup>™</sup>. While general in nature, the procedures and recommendations discussed herein are based upon proven procedures and equipment user experience representing a variety of fleet types and sizes. Whether or not you choose to implement VMRS directly, or through an outside vendor, this section should provide useful guidance in managing and streamlining the implementation process.
How you — the equipment user — choose to implement VMRS beyond the basic requirements is a matter of individual management judgement. However, following these guidelines increases your chances of making VMRS work for your operation.
The best means of ensuring successful implementation of VMRS is through:
- full management participation during initial implementation,
- adequate training of all personnel in VMRS fundamentals, and;
- action upon the information produced by VMRS.
#### **Implementation Preparation**
A fleet maintenance information system should be one of several equipment history subsystems capable of providing uniform source data and information to all relevant fleet management functions. The principle is simple: data is captured once, then redistributed as needed in appropriate formats. Eliminating duplication minimizes information errors.
Right from the start, all managers who will derive information from VMRS should be involved in the process of determining how the information will be formatted. Top management should support the formation of a implementation committee which will represent appropriate management functions and assist in implementing VMRS. It's important that all members of this committee approach this task free of any preconceived ideas. Finally, one person should be given responsibility and authority to lead this team effort.
There are 17 basic steps to implementing VMRS from scratch. These are:
- Define the company purpose for implementing VMRS.
- 2. Assign a VMRS project manager.
- 3. Designate participating departments.
- 4. Obtain all appropriate VMRS<sup>™</sup> references, such as this *Handbook*.
- 5. Contact and visit fleets currently using VMRS.
- 6. Conduct a systems study of current practices.
- Approve the findings of the systems study from Step 6.
- 8. Develop a VMRS implementation plan.
- 9. Design the new fleet management system around VMRS.
- Develop all necessary data processing system applications (i.e., maintenance management software or paper-based data entry system) either internally, or through an outside supplier.
- 11. Develop/obtain VMRS training materials and support procedures.
- 12. Train all necessary personnel.
- 13. "Beta" test the VMRS system.
- 14. Document VMRS system performance.
- 15. Modify training materials and procedures if necessary.
- 16. Fully implement VMRS.
- Review, evaluate, enhance and expand VMRS usage either continually or periodically.
Failure to follow these 17 steps has proven troublesome for fleets trying to haphazardly implement VMRS. Shortcuts to this process inevitably lead to incomplete and ineffective systems, duplication of work, and systems interface incompatibility. The only way to avoid such waste is through the planned, progressive and orderly development of integrated systems. Let's now examine each of the 17 steps in detail.
## 1. Define the Company Purpose for Implementing VMRS.
This definition should be general in scope, reflecting the goals of what VMRS should ultimately provide the company. This step helps establish a company-wide common objective.
An example of such a purpose statement is:
"The purpose of the Equipment and Maintenance Management Information System is to provide essential information for the future and current procurement, operation, and maintenance of the company's automotive and associated equipment. Uniform financial, usage, and utilization information on individual pieces of equipment, maintenance parts, labor charges, and maintenance facilities should be available to all departments in the detail and format they separately require."
#### 2. Assign a VMRS project manager.
The project manager is the team leader and should be selected with care. This person must have:
- a degree of recognition within the organization,
- time to devote to the project,
- an overall understanding of various departmental functions, responsibilities, and interrelationships, and;
- possess the ability to develop consensus between subordinates, supervisors and peers.
It's a mistake to simply assign this role to the company's data processing manager just because someone expects that this person should design the system.
#### 3. Designate participating departments.
Initially, it may not be possible to designate all participants to the project. However, it is essential to include, as soon as possible, managers from all relevant departments, such as maintenance, accounting, equipment and data processing. Other participants may represent operations, environmental, and safety departments, for example. As the project evolves, participants may be added or removed as needed.

Good data samples should be used to beta test the system, and can best be obtained by following the procedures outlined previously.

Furthermore, the two systems can be run on a parallel basis. Problems uncovered should be shared with those concerned, and resolved. Subsequently, programming changes can be made.
Test/sample reports should be provided to all users for review, comments, recommendations, and approval. Finally, changes should be made as necessary.

- prepare systems operations flow charts and instructions.
- prepare data entry instructions.
- document the system.
- document applications programming.
# 15. Write or modify training materials and procedures as necessary.
This step creates institutional memory of how the system functions. As personnel change, these materials will increase in value. It is essential that formal procedural references be available to train new and current personnel. Development and maintenance of the systems and procedures manual should be assigned to the one manager who has the fullest understanding of the system at the operating level.
#### 16. Fully implement VMRS.
The actual implementation of a VMRS-based maintenance management system can be accomplished in several ways. If an existing system has been in operation, the two systems can be run parallel, beyond the test phase, so as to thoroughly familiarize all persons with all phases of the new system.
If, on the other hand, management believes the system can be implemented without further trial and training, a set date can be established to terminate the old system and begin the new system.
If multiple shop locations are involved, it may be a good idea to phase in the new system at one or several sites at a time. This permits onsite supervision by management to ensure implementation is off to a good start.
It may be a good idea to convert historical data to the new system, if justifiable.
Closely monitor the new system and evaluate its output and the relationship it has with other systems. Fine tuning is easier to accomplish earlier, rather than later. Additionally, solicit feedback from all relevant parties—from the shop floor to the front office—so necessary adjustments can be made as quickly as possible.
# 17. Review, evaluate, enhance and expand VMRS usage, either continually or periodically.
All management information systems should undergo periodic review or audit to determine whether or not they are functioning efficiently. For example, the equipment that supports the system may become less efficient and/or more costly as technology improves.
New management information requirements may overlook the fact that the basic information sought may be derived from data already being recorded, or available to be recorded in the existing system. Similarly, new information requirements may be met with data available for processing from both the maintenance and other information systems.
Enhancements should be treated as if one were establishing a new system. The same considerations should be applied even to "one-time only" projects. Finally, the continuing process of fine-tuning should seek as its goal the best possible information at the least expense.
#### Conclusion
Equipment and maintenance reporting is not a speciality. It is a major component of any fleet's data reporting and analysis effort. As such, maintenance reporting should be a thoroughly integrated component of both the basic fleet management information system and its subsidiary systems.
# 4. Preparing Effective Equipment Maintenance Management Reports
#### Introduction
Preparing meaningful equipment maintenance management reports is a task that continually challenges even the best fleet managers and information specialists. The variety of such reports is almost endless, and basic maintenance data is processed and presented in almost as many formats as there are reports and equipment users.
Reports are in no way a substitute for the knowledge and judgement of a professional equipment manager. The manager and information systems specialist should work together to define what information is needed and how it can be most effectively presented.
One reason for such a variety of maintenance reports is the very variety of maintenance variables that can be identified, measured, and compared. These variables include:
- individual equipment units
- locations of maintenance activities
- causes of equipment failures
- equipment systems
- equipment subsystems
- individual equipment components.
Each of these factors have their own separate characteristics and reliability, adding to the complexity of maintenance reports.
VMRS provides a system of equipment maintenance recordkeeping that enables managers to assemble information needed to plan and control maintenance functions. VMRS provides data element definitions and codes, as well as the basic forms for recording equipment identification and maintenance data. Furthermore, the codes provide the "handles" by which appropriate data items can be selected and processed in the data processing system to prepare useful management information reports. The format and content of management reports should reflect the needs and preferences of the managers who use them. Standardized reports that a rigidly structured and do not take into consideration the nature of the organization, the equipment and its operation are usually of little use.
There are seven key dimensions to management reports: content, detail, frame of reference, aids to analysis, readability, schedule, and economy. All reports should be evaluated for these attributes.
This section examines some equipment maintenance management reports, illustrating how various users have approached maintenance management reporting, the advantages and disadvantages of various approaches, and how the analysis of those approaches may provide guidelines for equipment maintenance reporting. The examples are not intended as specific recommendations of formatting and reporting, and should not be used for cost or other reference purposes.
#### **1.** Equipment Maintenance Cost Reports Report 4-1 is a weekly report which was prepared by a computer system. The report features columns for equipment identification number, VMRS systems code (Code Key 31), labor hours, labor amount, parts amount, and total amount. Several lines for each piece of equipment in these columns show each major component group (or preventive maintenance) which was serviced during the period. Column totals for
each piece of equipment indicate the maintenance performed at a company maintenance facility, in the field, at a company freight terminal, terminal facility, or at an outside maintenance shop.
This report also presents maintenance cost analyses by VMRS system code and by locations where work was performed. These analyses help users in identifying needs for further investigation or management action. The capability to use computers to generate such reports depends on coding of repair orders with VMRS. Presumably, the report user wishes to take action more quickly after the occurrence of the maintenance incident than would be afforded by a monthly report. Of course, comparisons are possible within the time period covered. Then, equipment is identified only by unit number. Unless that number can be mentally associated with make, model, year, and other further identification, the report user will have to refer to other reports or files for that information. # 6. Shop Start-Up Procedures for VMRS
As mentioned in Section 3, the key to successfully introducing VMRS into a fleet maintenance management system is the development of a logical implementation plan. This section offers guidance for logically implementing VMRS at the shop level.
Although VMRS implementation requires the cooperation of maintenance, finance, systems, and data processing departments within a company, it is still the equipment and maintenance manager's responsibility to implement VMRS at the shop level. Because the adoption of any new system can spur resistance among employees, it's important for the maintenance manager to anticipate and minimize resistance through effective planning, motivation, training, and supervision.
This section covers the following implementation topics:
- Initial Planning
- Repair Order Forms and Procedures
- Shop Personnel Training
- Shop and Central Office File Preparation
- Equipment Master Record Forms
- Procedures Manuals Development
- Follow-up Procedures
# Initial Planning for VMRS Implementation
There are two basic methods that can be used to introduce the VMRS<sup>™</sup> Repair Order and Equipment Master Record Forms into the maintenance shop. The first is to wait until the new VMRSbased management information system has been developed and tested, and perhaps even operate both old and new systems in parallel for a time. The second is to implement the forms immediately.
In the wait and see approach, Equipment Master Records are completed prior to the introduction of the repair order forms. Equipment data files are constructed and tested, but no live VMRS data is accumulated. When management is certain that the new system will work, the VMRS Repair Order Form is introduced, and data begins accumulating.
The problem with the "wait and see" approach is a major time lag is created. Several or many months may pass before meaningful data is gathered for reporting purposes. Introducing the Repair Order Form immediately is a more positive and beneficial approach.
An objective comparison of the VMRS<sup>™</sup> Repair Order Form to the fleet's existing repair order will probably show that the VMRS form can capture all of the information currently being recorded—plus a whole lot more. Prompt use of the VMRS Repair Order Form ensures data collection begins without delay, speeding implementation.
Coordination both within and outside the maintenance department should occur prior to using the Repair Order Form in the shop. Contact with the accounting and data processing departments should be made to determine their current and future information requirements. For example, there are two distinct VMRS<sup>TM</sup> Repair Order Forms—Repair Order (*Form 6*) and Special Repair Order (*Form 7*). The major difference between these forms is that the Special Repair Order form provides for the manual extension and entry of parts and labor cost. Both forms should meet fleet requirements.
As part of the planning, development, and test process for implementation of the overall system, some larger fleets have found it worthwhile to initially operate a VMRS-based system on a manual basis. Smaller fleets lacking access to computer-based systems will do this anyway.
In larger fleets, VMRS-coded data may be collected on a group of like pieces of equipment. This data is then processed manually in the format of proposed computer-generated reports. This technique offers opportunities for systems evaluation, for testing and revising reports, for gaining an actual working knowledge of the system and its potential, and for training users of the system. **Important Tip:** Make every effort to have data from the Repair Order Forms entered into the fleet maintenance management system *in the maintenance shop!*

# Shop and Central Office Files
A maintenance (equipment) file folder should be established for each piece of equipment. Fleets operating more than one maintenance facility and having equipment domiciled at these different locations should establish a file for each piece of equipment at its domiciled location, as well as at the central maintenance office.
Files of domiciled equipment should be reviewed prior to writing or issuing a repair order to a mechanic. This will assist in identifying the cause of the problem (especially in instances of repeat or frequent work in the same VMRS system) rather than treatment of its symptoms. Obvious indicators of recent work on the same component for non-domiciled equipment should cause the mechanic to bring his observations to the attention of the supervisor. A request by the shop to the central maintenance office for a check of the equipment's maintenance file can then be made. The time required by this procedure to save costly but ineffective repeat work may result in significant savings over the remaining life of the equipment, or even an entire range of equipment utilizing the same component(s).
When the VMRS Equipment File is used as designed, the equipment's maintenance profile offers ready indicators of repeat work. File personnel can be taught to identify these indicators and bring them to the attention of technically qualified persons for further evaluation and appropriate action.
# **Equipment Master Record Forms**
Equipment identification data should enter the equipment and maintenance recordkeeping system once, at its source! This data should then be distributed, or made available to all departments requiring them in whole or in part. The VMRS Equipment Master Record Form provides the means of recording essential equipment identification data. Detailed instructions for the preparation of these forms are found elsewhere in this *Handbook*.
Equipment Master Record preparation may require data input from one or more departments. Equipment characteristics and component data may be provided by the equipment and maintenance department, financial data by the accounting department, and work assignment, location, and licensing data by the operations department. Responsibility for preparing master records should be assigned to one department which will obtain all necessary data companywide.
Copies of Equipment Master Records should be filed in individual equipment file folders. Fax additional copies when required. Financial data need not be recorded on copies of master records maintained in maintenance facility equipment files which are accessible to all personnel. All but financial data can be entered on the copy of the master record in the central equipment file after entry.
Preparing Equipment Master Record forms can normally best be accomplished by maintenance facility administrative personnel. These individuals are well suited for this task because of their general knowledge of the fleet's equipment, and descriptive terminology used. Maintenance personnel are generally better equipped to obtain the data needed to properly complete master records. Sources of equipment identification data are lineset tickets, specification sheets, licensing and registration records. As a last resort, physical inspection of the equipment may be needed to produce necessary data. The value of time spent collecting data on equipment that will be traded within 12-18 months should be considered. Skeletonized records may suffice in such cases. What is important is that all equipment be entered in the total fleet inventory and that all new equipment entering the fleet have a master record prepared prior to service entry.
Detail to be entered on Equipment Master Record forms is a subjective choice for each fleet. Because record preparation usually occurs only once while the equipment is in fleet service, the value of complete versus partial data should be weighed. Completed master records can be the source of virtually unlimited maintenance data and information. Conversely, partially completed master records are ultimately a limiting factor to a fleet. Experience has shown that as users become more experienced in VMRS, they demand more information from it than was initially envisioned.
The VMRS Equipment Master Record may also be used for both developing and listing new equipment and component specifications to aid in soliciting uniform bids from equipment manufacturers.
# **Developing a Procedures Manual**
Procedure manuals document how a system works and what roles each participant plays in its operation. The manual's purpose is to ensure standardization necessary for effectively implementing system goals. Non-standardized preparation of repair order forms will cause problems in data entry and report preparation. Under these conditions, the value of the maintenance information produced suffers and company assets are wasted.
Good procedure manuals are not set in concrete, however. Consider them dynamic references which can be changed, when necessary, by the issuing authority. A loose-leaf ringed-binder format is recommended.
Procedure manuals are only useful if used. They must be made available to the user and prepared in legible formats that will encourage their use. Their arrangement should suit the user's needs, not the author's literary preferences.
A table of contents and index should be included to assist the user's ability to access the information. Index tab dividers are a good means of separating the manual into logical groups of related material. Procedure manuals should contain flowcharts, diagrams, documents and any other illustrations that will assist users in understanding specific procedures.
Descriptions of individual data entry procedures on forms should follow the arrangement of the form and the progressive sequence in which the data is to be entered. Use of sample forms annotated with sequential procedure numbers keyed to written instructions is recommended. Copies of completed forms should also be included when appropriate. Each procedure described should begin on a new page. The purpose and/or objective of the procedure should be simply stated in a single sentence at the beginning of the procedure being described. If the overall procedure began prior to the application of the specific procedure at hand, the previous procedure should be identified. Subsequently, when the specific procedure is completed, the concluding sentence should either describe who does what or state that the overall procedure is now complete.
Users of procedure manuals are an invaluable source for manual improvement. Encourage user input. Test suggestions in a controlled setting, and implement if effective.
Management should routinely spot check procedure manuals to ensure changes have been entered correctly, outdated material has been discarded, and that persons using the manual are aware of any changes made.
# Follow-up Procedures
Training programs and procedure manuals alone do not guarantee that data input will be of an acceptable quality. Follow-up procedures are a must for ensuring data quality.
Supervision is one follow-up method of maintaining data input quality. Repair order forms must be checked by supervisors when completed by mechanics and parts specialists. Errors must be corrected immediately.
Supervisors have two choices: They can correct the errors and eventually become edit clerks, or they can have the appropriate individuals correct the entries and thereby remain functional supervisors.
Periodic spot checking or auditing of repair order forms is a good idea. Errors noted should be promptly brought to the attention of supervisors for further correction. This can be troublesome if the maintenance facility in question is distant from the maintenance manger's central office. In these cases, well-developed and documented procedures — reinforced by supervision, auditing, and data editing routines — will help minimize problems. People are generally happier and more productive when they have some understanding of their role in the organization, what they are doing, and can have their questions answered. Contact with subordinates, and auditing, will help achieve accurate implementation of VMRS at all levels.

# Instructions for Completing The VMRS Equipment File (*Form 30*)
#### Introduction
The VMRS<sup>™</sup> Equipment File (*Form 30*) satisfies two basic requirements for efficient fleet management.
- It provides a simple and effective means of ensuring compliance with Section 396.2 of the Federal Motor Vehicle Safety Regulations.
- It enhances both daily and long-term fleet maintenance operations and record keeping requirements by providing:
- a descriptive ready reference of each unit, its major components and service function within the fleet.
- a visual record of the maintenance history of the unit.
- a means of filing, in a single location and safeguarding, all pertinent records of the unit required by both regulatory agencies, as well as the demands of effective fleet management.
A VMRS Equipment File should be established for each major unit of fleet equipment at the time of acquisition or entry into service. Furthermore, no maintenance service— or repair order — should begin on a piece of equipment until the shop foreman checks the equipment's history. Equipment files should be readily accessible to persons responsible for preparing repair orders for this very purpose.
In cases where multiple maintenance facilities require centralized record keeping, these files provide a ready means for semi-skilled persons to initially identify repetitive work on the same equipment system. In such cases, the complete file being brought to the prompt attention of technically qualified persons may result in significant financial savings.
While designed for use in conjunction with VMRS, the VMRS Equipment File has proven itself to be highly effective in its use by fleets which have not yet implemented VMRS.
### Establishing VMRS Equipment Files
#### 1. General
Enter that information which best suits the nature of your operation and the requirements of Section 396.2 of the Federal Motor Carrier Safety Regulations.
NOTE: The VMRS Equipment File is designed for records of power units—mainly trucks and tractors. However, it may also be effectively used for keeping records on other powered and non-powered pieces of equipment.
Use of this file will enable all levels of management to have a quick, visible profile of the maintenance service record of each unit maintained. It is not intended that this file replace the detailed maintenance information obtainable from maintenance information systems. This file is principally for shop level use with domiciled equipment. It may also be of value in central maintenance file systems.
The contents of this File should contain the following items:
- Equipment Master Record, line set tickets, "Spec" sheets, or similar documents which identify or describe the equipment and its components.

# Instructions for Completing The VMRS Repair Order Log (*Form 20/21*)
#### Introduction
The VMRS<sup>™</sup> Repair Order Log (Form 20) provides fleet management with a way to help control and measure performance within its maintenance shop operations. It provides maintenance supervisors with a simple, consolidated record of repair orders written and their status (i.e., open, completed, work delayed, etc.). The second copy of the log may be used as an analysis tool of shop operations and as a data entry form for maintenance management information systems. The subsequent processing of this data can provide management with meaningful information as described further in this section. With this information at hand, supervisors can better maintain control of the assignment of the work force and the allocation of the available work space.
The one-part VMRS Repair Order Log (*Form 21*) can be used in the maintenance shop to assist shop foremen and shift supervisors in scheduling work priority, ensuring continuity of work from shift-to-shift, responding to inquires as to the availability of equipment, and aiding in monitoring the status of work in progress. When delays occur, they should be entered in the log so that corrective action can be taken, responsible managers notified, and scheduling adjustments made to keep the maintenance facility operating efficiently.

#### Using the Repair Order Log
Data obtained from the Repair Order Log and other maintenance data sources should be an integral part of any fleet maintenance management information system.
The primary purpose of analyzing data from shop logs is to identify shop locations having difficulty completing their jobs on schedule. It can also aid in determining the causes of time overruns so appropriate corrective actions can be taken. Bear in mind, schedule completion times may be unrealistic due to pressures from outside the shop or of ineffective estimating techniques. An appropriate management level should consider evidence that such problems exist and take steps to speed improvements.
If the scheduled out times are realistic, failure analysis will highlight problems which interfere with shop and equipment operations productivity. ## Appendix: The Complete VMRS<sup>™</sup> Coding Convention — Code Keys 1- 84
The heart of VMRS<sup>™</sup> is the VMRS coding convention. This coding convention is divided into separate and distinct data sets called "Code Keys." Within each individual "Code Key," are individual values that identify and classify various aspects of maintenance, equipment, and maintenance management.
Individuals often mistakenly think VMRS is just the nine digit code that identifies parts. In reality, this "component" code — which comes from VMRS Code Key 33 — is only one aspect of VMRS. There are many other Code Keys within the VMRS coding convention.
Code Keys 1-13 and 34-51 identify and classify vehicle characteristics, function and specifications. Because these Code Keys are used in completing the VMRS Equipment Master Record, they are often referred to as the "Equipment Master Record codes."
The codes within Code Key 1 describe equipment vocation (i.e., linehaul, utility, etc.). Code Keys 2-13 describe equipment category and type. Code Key 20 describes equipment status/ availability for service.
Code Key 34 identifies equipment manufacturers, suppliers and brands using a five-character alpha code developed exclusively for VMRS.
Code Key 35-40 and 47-48 describe major component configurations. Similarly, Code Keys 53-75 provide the means to record similar data for mechanical refrigeration and material handling equipment.
Code Key 79 offers position codes for components which may be used in more than one location, orientation or position. Code Key 80 identifies severity of service for various types of vehicle applications/vocations. Code Key 81 identifies types of claims for warranty processing. Code Key 82 describes driver/ operator vehicle complaints for warranty and driver condition report processing. Code Keys 83 and 84 pertain to warranty claim status and response.
VMRS "Instruction Sets" are composite codes - derived from combinations of various Code Keys - that serve as "equipment type codes" for power units, trailers, and converters. These Instruction Sets are numerical sentences, using individual Code Keys as building blocks or "words" to describe various aspects of equipment specification or labor activity. There are 15 VMRS Instruction Sets currently in use. (VMRS Instruction Sets were previously classified as Code Keys. Beginning with VMRS 2000 v.1.01, the term Instruction Set is used instead for these "composite" identifiers.)
This section offers a complete list of all VMRS Instruction Sets, Code Keys and their corresponding values. Together, they represent the most powerful coding convention available for classifying and identifying all aspects of equipment maintenance and maintenance management.
If you—the user—find deficiencies in these Code Keys, please call TMC. TMC staff will be happy to either locate existing codes or assign new codes for your operation. Only you—the end-user—can help VMRS remain a dynamic standard.

# Code Key 14: Reason for Repair
### Description and Purpose
Code Key 14 describes the reasons why work was performed on a unit. These codes fall into one of three specific categories:
- Maintenance or repairs directly attributable to a piece of equipment. This is work performed to maintain or restore equipment to a specified operating condition, which is directly attributable to its operation. This includes inspecting, repairing, or replacing any defective part or assembly which requires attention.
- Work performed based on management decision. Work which is not directly attributable equipment operation, such as a change to its original configuration, or rehabilitation to the extent that the costs incurred are capitalized. Also includes the special review, or inspection, of equipment so that information can be obtained for management decision purposes.
- Repairs caused by outside influence. This is worked performed which is not directly attributable equipment operation or based upon a management decision. Often many of the costs incurred in this category are subsequently reimbursed in whole or in part by an outside source.
#### Use
Code Key 14 is used when completing VMRS Repair Order forms (*Form 6*) and VMRS Special Repair Order forms (*Form 7*). Selecting the appropriate reason for repair is very important as it impacts management decisions made based on this information.

# Code Key 31: System Codes
### Description and Purpose
VMRS<sup>™</sup> uses a series of three-digit codes that readily and consistently identify specific equipment systems. For example, brakes are identified as a system by code 013. While these codes are the heart of the "common language" of VMRS and are a vital part of the VMRS concept, they are by themselves nothing more than coding conventions designed for use at all levels within the industry, from fleets to mechanics to manufacturers to suppliers of parts. In order to take advantage of the 3rd digit of the SYSTEM level Code (Code Key 31),TMC redefined the VMRS GROUP portion of the SYSTEM CODE in 2003 as follows:
- There are 10 groups within VMRS Code Key 31 (and CK 32, and CK 33 as well):
- X0X Cab, Climate Control, Instrumentation, & Aerodynamic Devices Group
- X1X Chassis Group
- X2X Drivetrain Group
- X3X Electrical Group
- X4X Engine / Motor Systems Group
- X5X Accessories Group
- X6X Equipment Dependent Attachments
- X7X Bodies & Vessels Group
- X8X Heating & Refrigeration Group
- X9X Bulk Product Transfer Systems Group
- Under this structure, the 2nd digit of the SYSTEM CODE, identifies the GROUP CODE.
- The 1st and 3rd digits vary to permit additional systems within a GROUP.
- Under the old VMRS 2000<sup>™</sup> (versions 1.00-1.02) structure, the 1st & 2nd digits identified the GROUP CODE.
- Under the original VMRS structure (pre-1997), the first digit of the 2-digit SYSTEM CODE identified the GROUP CODE.
This change in convention preserves the traditional definition of GROUPS within systems and is consistently backward compatible with all previous versions of VMRS and VMRS 2000<sup>™</sup>.

# **Code Key 79: Position Codes**
#### Description and Purpose
Position codes apply where multiples of an identical component performing the same function within the VMRS assembly can be installed on the same unit (equipment).
The following rules apply when assigning a "position" code:
- 1. The equipment configuration at the time the work is performed becomes the determining factor when assigning a "position" code. All position codes are based on the drivers seat perspective. The hierarchy is as follows: Front to rear; Left to right; Top to bottom; Sequential.
- 2. Position codes are a function of the specific VMRS assembly being reported.
- 3. When more than one (1) of the same component exists within the hierarchy of a VMRS assembly, then a sequence code must be used.
- 4. Application of "position" codes follows the schema detailed below.
- 5. Position coding is independent of manufacturer's specific numbering convention (example: engines, transmissions, differentials).
- 6. For engines, transmissions and differentials, side planes are defined by the manufacturer's accepted orientation and are installation independent.
Originally, Code Key 79 was a composite of three subsets or elements: Code Key 79a—Side Code; Code Key 79b—Orientation Code; and Code Key 79c—Sequence Code. The original code schema appears at the bottom of this page.
#### New Code Structure
In 2007, TMC's membership approved a restructuring of the coding schema. The updated Code Key 79 defines position through two Code Key subsets or elements: Code Key 79a: Side and Orientation Code and Code Key 79b: Sequence Code.
#### Code Key 79a Side and Orientation Code
This two-digit alpha-numeric code combines the former Side and Orientation elements into one. Codes define the side and orientation (first—front to rear, second—left to right, third—top to bottom; fourth—inner to outer) relative to the driver seat orientation. The code must be considered in conjunction with Code Key 33: Component Code.
#### Code Key 79b Sequence Code
This code remains as originally defined—a numeric, two-digit sequential code. Taken together, these subsets would define position in a four-digit code: Example: 02-01 where
> 02=Front Left 01=Position 1 or First
An alternate code schema is offered for Code Key 79a: Side and Orientation Code which consists of four data elements, each of which is expressed as a alpha character. This schema is easier to remember and visually intuative.
Data Element 1 defines Front or Rear where: F=Front; R=Rear; X= not applicable. Data Element 2 defines Left or Right where: L=Left; R=Right; X= not applicable. Data Element 3 defines Top/Upper or Bottom/Lower where:
T=Top/Upper; B=Bottom/Lower; X=not applicable
Data Element 4 defines Inner, Outer, Center, Inner and Outer and All where: I=Inner; O=Outer; C=Center; E=Inner and Outer; A=All; X=not applicable.
The sole exception to this schema is the definition of circular, which is expressed as "C C C C".

# Code Key 80: Severity of Service

- 04 Light service, P&D

#### Definitions
#### 01 Light Service, linehaul
- Transportation over long distances in high mileage operations (over 60,000 miles per year.)
- Equipment travels greater than 30 miles between stops.
- Operation on road surfaces of good to excellent concrete or asphalt. (typical)
- Duty is 100 percent load going and 60 percent (or less) load return with grades encountered normally not exceeding eight percent.
#### 02 Moderate Service, linehaul
- Transportation of freight over long distances in high mileage operations (over 60,000 miles per year.)
- Equipment travels greater than 30 miles between stops.
- Operation on road surfaces of good to excellent concrete or asphalt. (typical)
- Duty is loaded full time (more than 60 percent load return) with grades encountered normally not exceeding eight percent.
#### 03 Severe Service, linehaul
- Transportation of freight over long distances in high mileage operations (over 60,000 miles per year.)
- Equipment travels greater than 30 miles between stops.
- Operation on Turnpike only except for loading and unloading at nearby terminals. Road surfaces of good to excellent concrete or asphalt. (typical)
- Duty is loaded full time (more than 60 percent load return) with grades encountered not exceeding three percent.
#### 04 Light Service, pickup and delivery
- Pickup and delivery service within cities and / or suburban areas (short haul, less than 60,000 miles per year).
- Operation on paved road surfaces of concrete or asphalt.
- Grades are defined as light (to about eight percent) which would be typical of geographic areas of operation such as metropolitan Chicago or Detroit.
- Approximately three miles between starts/stops (average). 100 percent load going /40 percent load return (typical).
#### 05 Moderate Service, pickup and delivery
- Pickup and delivery service within cities and / or suburban areas (short haul, less than 60,000 miles per year).
- Operation on paved road surfaces of concrete or asphalt.
- Grades are defined as moderate (to about 12 percent) which would be typical of geographic areas of operation such as metropolitan Atlanta or Seattle.
- Approximately three miles between starts/stops (average). 100 percent load going /40 percent load return (typical).
#### 06 Severe Service, pickup and delivery
- Pickup and delivery service within cities and/or suburban areas (short haul, less than 60,000 miles per year).
- Operation on paved road surfaces of concrete or asphalt.
- Grades are defined as severe (to about 20 percent) which would be typical of geographic areas of operation such as metropolitan Pittsburgh or San Francisco.
- Approximately three miles between starts/stops (average). 100 percent load going /40 percent load return (typical).

# Appendix IIa: Code Key 32 – Assembly Codes (Alphabetical Order)
#### Description, Purpose and Use
Through the use of assembly level codes, VMRS provides additional capability to further define Code Key 31's System Codes. The first classification below the system level is referred to as the assembly. At this level, all major groupings within each system are broken out and reported through the use of a three digit code. These, when used with their system prefix, identify the specific assembly within a vehicle. For example, front brakes and drums can be identified by a combination of the System and Assembly Code 013-001.
While these codes are the heart of the "common language" of VMRS and are a vital part of the VMRS concept, they are by themselves nothing more than coding conventions designed for use at all levels within the industry—fleets, mechanics, manufacturers, and parts suppliers.
