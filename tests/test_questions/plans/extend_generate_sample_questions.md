# Plan: Extend Sample Question Generation from Vendor Data

## Objective

Extend `generate_sample_questions.py` to programmatically generate stakeholder test questions and oracle answers from `vendor data/checked/Motors Part Cleanup - Return Data.csv`, aligned with `tests/test_questions/TEST_PLAN.md`.

## Outputs (Per TEST_PLAN.md)

1) Question list: `tests/test_questions/questions.md`
- Include stable `test_id`s with question text.
- Track counts by category and expected behavior.
- Recommended format: a Markdown table with columns `test_id`, `category`, `expected_behavior`, `question_text`.

2) Oracle answers: `tests/test_questions/expected_answers.json` (or `.csv`)
- One entry per `test_id`, matching the TEST_PLAN schema.

3) Execution log: `tests/test_questions/test_log.csv`
- Not generated by this script. It is produced during test execution by the MCP harness.

## Categories to Generate (from TEST_PLAN.md)

| Category | Question Pattern | Source Fields |
|----------|-----------------|---------------|
| part_number_exact | "What is the VMRS code for part number {PART}?" | PART, VMRS, SYSTEM_, ASSEMBLY_, COMPONENT_ |
| vendor_part_number | "What is the VMRS code for {MANUFACTURER} part {PART}?" | PART, MANUFACTURER, VMRS, etc. |
| description_exact | "What is the VMRS code for {DESCRIPTION}?" | DESCRIPTION, VMRS, etc. |
| description_partial_typo | "What is the VMRS code for {DESCRIPTION_PARTIAL_OR_TYPO}?" | DESCRIPTION (partial/typo) |
| hierarchy_navigation | "What is the hierarchy for VMRS code {VMRS}?" | VMRS, SYSTEM_, ASSEMBLY_, COMPONENT_ |
| vendor_mapping_from_vmrs | "What vendor parts map to VMRS code {VMRS}?" | VMRS, list of matching parts |
| validation | "Is {VMRS} a valid VMRS code?" | VMRS, SYSTEM_, ASSEMBLY_, COMPONENT_ |
| comparison | "Do parts {PART_A} and {PART_B} have the same VMRS code?" | Two rows |

## Selection Criteria from Vendor CSV

1. **Filter**: Only rows with `Match >= 1.0` (high confidence)
2. **Sample**: Select diverse examples per category
3. **Coverage**: Include different SYSTEM_ values, MANUFACTURER values
4. **Edge cases**: Include some KNOWN_ABSENT (fabricated invalid inputs) and AMBIGUOUS cases when multiple parts map to similar descriptions or VMRS prefixes
5. **Source of fields**: Part numbers, manufacturer names, descriptions, VMRS codes, and hierarchy labels are all pulled from `vendor data/checked/Motors Part Cleanup - Return Data.csv` for generated questions and oracle entries; only `test_id` values are synthesized.

```json
  "expected_hierarchy": {
    "system": {"code": "001", "name": "AIR CONDITIONING..."},

    "component": {"code": "001-001-062", "name": "CONDENSER ASSEMBLY..."}
  },
  "acceptable_candidates": ["001-001-062"],
  "vendor_parts": [{"part": "2591836C93", "manufacturer": "INTERNATIONAL"}]
}
```

## Implementation Steps

1. Add or extend a `generate` subcommand to emit `questions.md` and `expected_answers.json`.
2. Load vendor CSV, filter by Match >= 1.0.
3. For each category, select N representative rows with diversity across SYSTEM_ and MANUFACTURER.
4. Generate `question_text` using pattern templates and assign stable `test_id`s.
5. Build oracle entries using the TEST_PLAN schema (expected code, hierarchy, acceptable candidates, vendor parts).
6. Write `tests/test_questions/questions.md` (table or list) and `tests/test_questions/expected_answers.json`.

## CLI

```bash
python generate_sample_questions.py generate \
  --vendor-csv "vendor data/checked/Motors Part Cleanup - Return Data.csv" \
  --questions-out tests/test_questions/questions.md \
  --oracle-out tests/test_questions/expected_answers.json \
  --min-confidence 1.0 \
  --count 10 \
  --seed 42
```
